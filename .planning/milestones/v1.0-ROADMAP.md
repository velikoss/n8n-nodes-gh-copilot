# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-01-19
**Phases:** 1-5
**Total Plans:** 12

## Overview

This roadmap delivered an n8n chat model sub-node that connects GitHub Copilot's API to n8n's AI Agent workflows. The journey started with authentication infrastructure (the foundation everything else depends on), built the LangChain-compatible model layer, wired it into n8n's sub-node system with model selection, and finished with branding, polish, and npm distribution. Each phase delivered a testable capability.

## Phases

### Phase 1: Authentication

**Goal**: Users can authenticate with GitHub Copilot and obtain valid API credentials
**Depends on**: Nothing (first phase)
**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04, AUTH-05
**Success Criteria** (what must be TRUE):
  1. User can initiate device code flow and see verification URL with code
  2. Node correctly polls for authorization completion (per RFC 8628)
  3. Access token is exchanged for Copilot API key
  4. API endpoint is dynamically discovered (not hardcoded)
  5. Credential test function validates authentication works

### Phase 2: LangChain Model

**Goal**: A LangChain-compatible chat model that works with Copilot's API

  4. Model instance can be used directly by AI Agent node

## Milestone Summary

**Key Decisions:**

- Used VSCode Copilot client ID (Iv1.b507a08c87ecfe98) for device flow
- NodeNext module resolution for modern ESM/CJS interop
- Wrap ChatOpenAI rather than extend BaseChatModel directly (leverages retry logic)
- Required IDE headers: Editor-Version, Editor-Plugin-Version, Copilot-Integration-Id
- NodeConnectionTypes (const object) instead of NodeConnectionType enum
- PNG icon format for n8n nodes (192x192 RGBA)
- Package renamed to n8n-nodes-gh-copilot-lm (original name taken on npm)
- Repository: github.com/ssccio/n8n-nodes-gh-copilot

**Issues Resolved:**

- Dynamic endpoint discovery required for different subscription SKUs (Business vs Individual)
- System message transformation needed for Copilot API compatibility
- IDE headers required for API authentication
- Package name conflict resolved by using alternative name

**Technical Debt Incurred:**

None - all implementations complete without TODOs or FIXMEs.
